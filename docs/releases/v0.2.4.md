# CinePresence 0.2.4

Fixes a browser reporting failure that could prevent automatic handoff between playing tabs.

- A temporary message failure no longer permanently silences a tab. Pause and resume reports recover automatically.
- Newly inserted video players report play/pause events immediately, without waiting for the next polling tick.
- Activating a tab, completing a page load, restarting the companion worker, or returning through browser history refreshes playback. Stale background samples are checked again before they expire.
- Older cached documents cannot overwrite or remove a newer player's state.
- Automatic selection still keeps the first playing source until it pauses or stops. Spotify, social feeds, and the other excluded platforms remain blocked.

Install **CinePresence-0.2.4-Setup-win-x64.exe**, or extract **CinePresence-0.2.4-win-x64.zip** for portable use. Your saved settings are preserved.

**After updating:** reload CinePresence Companion in `edge://extensions` or `chrome://extensions`, then refresh all open playback tabs. Use **Automatic** in CinePresence → Sources; a manually pinned source stays pinned while paused.

Validation: **167 .NET tests and 25 TypeScript tests passed**, covering two browser tabs with different titles, embedded playback, pause/resume handoff, message failure recovery, dynamic players, worker rediscovery, history navigation, and existing platform restrictions. The old 0.2.3 content script reproduces the stuck-Playing failure in the regression fixture; the updated script recovers to Paused. Live playback on the user's sites and the final Discord activity still require a browser retest after reloading.

Build note: NuGet's audit endpoints were unavailable. This build used the unchanged cached dependencies; a fresh vulnerability audit could not complete. Repository audit settings remain enabled.
